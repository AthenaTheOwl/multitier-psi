# the supplier dictionary belongs in the threat model

method update: october 18, 2026. proposed experiments below are not reported as executed results.

the protocol operates on canonical supplier identifiers prepared before intersection. privacy therefore depends on the preprocessing and identifier universe as well as the cryptographic exchange. a party with a small guessed supplier dictionary can test hypotheses across repeated sessions; aliases or inconsistent tier traversal can also create false nonmatches without any protocol failure.

the local `show` demonstration prints both fixture parties' unique suppliers to explain the scenario. that local demonstration has broader visibility than a party-scoped intersection receipt. keep those output contracts explicit when describing leakage. a schema allowlist or deterministic transcript test cannot establish a cryptographic security proof.

a bounded next test uses two aliases for one synthetic supplier, an intentionally ambiguous alias, and a tier cycle. the resolver should produce a reviewable mapping, decline ambiguity, and terminate traversal deterministically. a separate session-level test should record repeated-query visibility and dictionary version. production claims require an audited construction and an explicit adversary model. no real supplier list or private drive material belongs in the fixtures.
